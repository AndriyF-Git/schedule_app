# AI у SceduleApp

У проєкті реалізовано три AI-компоненти, кожен вирішує окрему задачу. Разом вони утворюють повний цикл: **оцінка → автогенерація → рекомендація**.

---

## Компонент 1 — Оцінювання якості розкладу

**Файл:** `schedule_app/ai/scoring.py`

### Проблема

Як визначити, наскільки добрим є розклад? Без метрики неможливо порівнювати алгоритми та навчати ML-модель.

### Рішення

Функція `score_schedule()` аналізує розклад за 7 критеріями — 4 жорсткими (HARD) та 3 м'якими (SOFT) — і повертає оцінку від 0 до 100.

| Критерій | Тип | Що перевіряє |
|---|---|---|
| H1 | HARD | Група не має двох пар одночасно |
| H2 | HARD | Викладач не веде дві пари одночасно |
| H3 | HARD | Група не має лише 1 пару на день (краще 0 або 2+) |
| H4 | HARD | Відсутність вільних вікон між парами для групи |
| S1 | SOFT | Не більше 4 пар на день |
| S3 | SOFT | Більше пар у середині тижня (вт–ср) |
| S5 | SOFT | Важкі предмети (складність 3) ставляться на 2-3 пару (10:45–14:00) |

Оцінка нормалізується відносно теоретично максимально досяжного результату для конкретного навантаження — тому 100/100 означає «найкращий можливий розклад для цих даних», а не абстрактний ідеал.

Цей компонент використовується всіма іншими: OR-Tools оптимізує за цими ж критеріями, RF навчається на оцінках цієї функції, а адмін бачить оцінку після кожної генерації.

## Компонент 2 — Оптимальна генерація (OR-Tools CP-SAT)

**Файл:** `schedule_app/ai/or_tools_generator.py`  
**Режим у UI:** 🤖 AI Генерація

### Проблема

Жадібний алгоритм розміщує пари випадково — бере перший вільний слот. Він швидкий, але не оптимальний: в середньому дає оцінку ~27/100.

### Рішення

**Constraint Programming** — метод точної оптимізації. Задача розкладу формулюється як математична модель:

- **Змінні:** для кожної сесії та кожного слота (день × час) — бінарна змінна `x = 1`, якщо сесія розміщена тут
- **Жорсткі обмеження:** накладаються математично, порушити неможливо
- **Цільова функція:** максимізувати суму м'яких критеріїв (S3, S5) мінус штрафи (H3)

Солвер **Google OR-Tools CP-SAT** перебирає простір рішень з відсіканням нежиттєздатних варіантів і знаходить оптимальний або найкращий за відведений час.

### Результати

| Показник | Жадібний | OR-Tools |
|---|---|---|
| Середня оцінка | ~27/100 | ~92/100 |
| H3 порушень (1 пара/день) | ~8 | 0 |
| Час роботи | < 1 с | 0.3–15 с |
| Детермінованість | різний щоразу | оптимальний |

Користувач задає ліміт часу (5–60 с). Якщо оптимальне рішення знайдено раніше — повертається відразу.

## Компонент 3 — Рекомендатор слотів (Random Forest)

**Файли:** `schedule_app/ai/recommender.py`, `ai/train_rf.py`, `ai/extract_features.py`  
**Режим у UI:** 📋 Ручне розміщення (AI Mode 2)

### Проблема

При ручному введенні розкладу адміністратор не знає, який слот для нової пари погіршить, а який покращить загальну якість. З 25 варіантів (5 днів × 5 часів) більшість можуть бути субоптимальними.

### Рішення

Двоетапний підхід:

#### Etап 1 — Look-ahead (без моделі)

Для кожного з 25 слотів симулюється розміщення нової пари, рахується `score_schedule()` для пробного розкладу. Слоти ранжуються за результатом. Топ-5 підсвічуються в сітці.

Перевага: не потребує навчання, працює одразу.  
Обмеження: трохи повільніший за ML при великих розкладах.

#### Etап 2 — Random Forest (після навчання)

ML-класифікатор навчається відрізняти слоти, які зустрічаються у якісних розкладах, від тих, що у поганих.

**Датасет:** 1 000 запусків жадібного алгоритму → кожна пара кожного розкладу = окремий рядок з 9 ознаками та міткою `high_quality = 1` якщо оцінка розкладу ≥ 40.

**9 ознак для кожного кандидата-слота:**

| Ознака | Значення |
|---|---|
| День тижня | 0 (Пн) — 4 (Пт) |
| Номер пари | 0 — 4 |
| Оптимальний час | 1 якщо пара 2–3 |
| Складність предмету | 1 / 2 / 3 |
| Пар групи цього дня | після розміщення |
| Пар викладача цього дня | після розміщення |
| Вікно для групи | 1/0 |
| Вікно для викладача | 1/0 |
| Один предмет на день | 1/0 (H3 ризик) |

**Навчання:** RandomForestClassifier (scikit-learn), 100 дерев, 80/20 train/test split.  
**Результат:** Accuracy ~0.89, F1 ~0.88.

При інференсі для кожного кандидата-слота обчислюється `P(high_quality)` — ймовірність того, що розміщення тут веде до якісного розкладу. Топ-5 слотів за цією ймовірністю відображаються в UI.

### Пайплайн навчання

```
1. generate_dataset.py   → 1 000 розкладів у data/schedules.jsonl
2. extract_features.py   → ~59 000 рядків у data/features.csv
3. train_rf.py           → ai/models/recommender.pkl
```

Після навчання Mode 2 автоматично перемикається з look-ahead на RF. Кнопка «🎓 Навчити RF модель» в адмін-панелі виконує всі три кроки за один клік.

## Загальна архітектура AI

```
                     Адміністратор
                          │
          ┌───────────────┼───────────────┐
          ▼               ▼               ▼
   Жадібна генерація  OR-Tools CP-SAT  Ручне розміщення
    (< 1 секунди)      (5–60 секунд)    (Mode 2)
          │               │               │
          └───────────────┴───────────────┘
                          │
                    score_schedule()
                    (оцінка 0–100)
                          │
              ┌───────────┴───────────┐
              ▼                       ▼
       Flash повідомлення      RF навчається
       адміністратору          на цих оцінках
```

Усі три режими обробляються однією функцією оцінювання — це гарантує, що OR-Tools оптимізує саме ті критерії, за якими рахується фінальна оцінка, а RF навчається на тих самих метриках.
